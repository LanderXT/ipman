# ipman v2.5.0 — branch-aware workspace context

ipman v2.5.0 adds automatic plan switching when the user changes git branches. `plan.activate` now records a branch → plan binding; `workspace.context_get` reads the current branch and surfaces the bound plan automatically — no manual `--activate` required after the first time. Two new ops expose and clean up bindings. The JSON protocol stays at `protocol_version: 2`; all existing ops are unchanged.

---

## What's new at a glance

| Change | Detail |
|---|---|
| `branch_contexts` table | New migration 0006. Maps `branch_name → active_plan_id` with an FK to `plans.id` ON DELETE RESTRICT (stale bindings survive plan close/archive; `context_get` skips terminal plans). |
| `plan.activate` | After updating `workspace_context`, upserts a row in `branch_contexts` for the current git branch. No-op when not in a git repo or in detached HEAD. |
| `workspace.context_get` | Detects the current branch, looks up its binding in `branch_contexts`, and overrides `active_plan_id` when a live (non-terminal) binding exists. Falls back to the global `workspace_context.active_plan_id` when no binding exists. Returns two new fields: `git_branch` (null outside a repo or in detached HEAD) and `branch_bound` (boolean). |
| `workspace.list_branch_bindings` | New op. Lists all branch → plan bindings with plan title and status. Useful for auditing after branch cleanup. |
| `workspace.unbind_branch` | New op. Removes the binding for the named branch (or the current branch when no `branch` param is supplied). Returns `deleted: true/false` so the caller can distinguish a hit from a no-op. |
| `-N` handoff view | Prepends a `Branch  <name>  (bound)` line (or `Branch  <name>` when on an unbound branch) so agents can see branch context at a glance. When no plan is active the message names the current branch: `on branch '<name>' — no plan bound`. |
| `git_helpers.c` | New C module. Reads the current branch from `.git/HEAD` directly — no subprocess. Handles both normal clones (`.git/` is a directory) and git worktrees (`.git` is a file containing `gitdir: <real-gitdir>`). |

Surface: **78 ops / 13 entities** (up from 76). DB schema: migration 0006.

## The workflow

```
# First time on a branch: activate a plan — the binding is registered automatically.
ipman --activate plan_42          # writes branch_contexts: main → 42

# Switch to a feature branch and activate a different plan.
git checkout -b feature/auth
ipman --activate plan_17          # writes branch_contexts: feature/auth → 17

# Switch back to main — no --activate needed.
git checkout main
ipman -N                          # Branch  main  (bound)  ← picks up plan 42 automatically
ipman -S                          # active_plan_id: 42

# Inspect all bindings.
ipman workspace.list_branch_bindings

# Remove a stale binding after deleting a branch.
ipman workspace.unbind_branch --branch feature/old-work
```

## New fields in `workspace.context_get`

```json
{
  "result": {
    "context": {
      "active_plan_id": 42,
      "git_branch": "main",
      "branch_bound": true,
      ...
    }
  }
}
```

- `git_branch`: string or null. Null when not in a git repo or in detached HEAD.
- `branch_bound`: boolean. `true` when `active_plan_id` was resolved from the branch binding rather than the global `workspace_context`.

---

## Fallback semantics

| Situation | `active_plan_id` source |
|---|---|
| In a git repo, current branch has a live binding | `branch_contexts` |
| In a git repo, no binding for current branch | `workspace_context` (global) |
| In a git repo, binding exists but plan is terminal | `workspace_context` (stale binding skipped) |
| Detached HEAD | `workspace_context` (global) |
| Not in a git repo | `workspace_context` (global) |

Stale bindings (pointing at closed/canceled/archived plans) are silently skipped rather than deleted, so the binding history survives plan lifecycle. Use `workspace.unbind_branch` to clean up explicitly.

---

## Migration

Migration 0006 runs automatically on first use. No manual action required.

For existing workspaces: no existing data is affected. `branch_contexts` starts empty; bindings accumulate as you `plan.activate` from now on.

---

## Implementation notes

- `ipman_git_current_branch` reads `.git/HEAD` with `fopen`/`fgets` — no `git` subprocess, no shell. This keeps ipman fast and dependency-free inside subagent environments where `git` may not be in `$PATH`.
- The worktree case (`.git` is a regular file) is handled: the file is parsed for `gitdir: <path>` and `HEAD` is read from the real gitdir.
- The branch binding upsert shares the transaction opened by `plan.activate`, so the binding is atomic with the workspace context update.
- `plan_is_nonterminal` guards the branch override in `context_get` to prevent a closed plan from hijacking the workspace.
