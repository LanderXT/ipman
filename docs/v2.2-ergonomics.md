# ipman v2.2 — discoverability and polish

ipman v2.2 is **purely additive over v2.1**. The JSON protocol stays at `protocol_version: 2`; no operations were added or removed; every v2.0/v2.1 client keeps working unchanged. What v2.2 polishes is the *human discovery surface*: the asymmetries between phase and task lifecycles, the noise on stderr, the hint when an envelope fails to parse, and the order in which the docs introduce the two surfaces.

If you only consume ipman through the JSON wire, **nothing in this release changes for you**. Skip to [Migration patterns](#migration-patterns) for the contract guarantees.

---

## What's new at a glance

| Group | Change | Replaces |
|---|---|---|
| Logging | `IPMAN_LOG` env var gates `info`-level logs (default: only `warn`/`error`) | Always-on info logs in v2.1 |
| Diagnostics | One-line tip on stderr when stdin can't be parsed as a request envelope, nudging the user toward `ipman --usage` and `ipman --next` | Bare `invalid_request` JSON with no follow-up |
| Docs | README leads with a *Five-minute tour* (CLI verbs); JSON wire moved to a clearly-labeled *Programmatic surface* section. `START-HERE.md` leads with `## Common Verbs (CLI)` before `## JSON Protocol` | JSON-first ordering |
| Lifecycle | `ipman --close-phase` and `ipman --cancel-phase` mirror the task verbs for phases | Hand-rolling `phase.close` JSON envelopes |

Every CLI verb resolves selectors the same way as in v2.1: numeric `id`, `uid` (e.g. `phase_3`), or `label` (resolved against the active plan).

## Phase lifecycle verbs

Before v2.2, the human CLI had `--start`, `--close`, `--cancel`, and `--defer` for tasks but **no equivalent for phases**. Closing a phase meant either leaving the workspace and hand-rolling a `phase.close` envelope, or piping JSON through `ipman` and parsing the response yourself. v2.2 closes that asymmetry with two named verbs.

### Close a phase

```sh
ipman --close-phase auth-rewrite \
  --summary "All migration tasks resolved" \
  --comment "Phase complete; rollback path validated"
```

```json
{"op":"phase.close","params":{
  "id":3,
  "outcome":"completed",
  "outcome_summary":"All migration tasks resolved",
  "closing_comment":"Phase complete; rollback path validated"
}}
```

Optional flags mirror task close: `--lessons`, `--open-items`, `--followup`. Every flag maps to the same field on the wire as `task.close`.

### Cancel a phase

```sh
ipman --cancel-phase auth-rewrite \
  --summary "Out of scope for v2.2" \
  --comment "Deprioritized after planning review"
```

```json
{"op":"phase.close","params":{
  "id":3,
  "outcome":"canceled",
  "outcome_summary":"Out of scope for v2.2",
  "closing_comment":"Deprioritized after planning review"
}}
```

Both verbs serialize to `phase.close` — the wire op is single-target and selects between resolutions via its `outcome` field. The CLI exposes two named verbs (rather than a polymorphic `--close`) so the audit trail in shell history matches the resolution recorded in closure memory.

### What's deliberately absent

- **No `--defer-phase`.** The wire has no `phase.defer` op; deferral is task-scoped only. Marking a whole phase blocked is what `phase.update` (with a status change) and standing instructions are for.
- **No git auto-capture.** `phase.close` does not accept `commit_sha` / `dirty` / `files_changed` — those belong on individual tasks where a single commit is meaningful. A phase typically aggregates many commits; capturing one would be misleading.
- **No `--validation` / `--decision`.** Same reason: structured evidence belongs on the task closure, where it can be tied to a single change.

### Preconditions and selector kind

Both verbs require the selector to resolve to a phase. Passing a task selector fails fast with a CLI-side message:

```
$ ipman --close-phase task_42 --summary x --comment y
ipman close-phase: selector `task_42` is a task, but this command requires phase
```

`phase.close` rejects the call when any child task is non-terminal — the wire enforces this and the CLI surfaces it verbatim:

```
$ ipman --close-phase auth-rewrite --summary "..." --comment "..."
ipman: phase has non-terminal tasks
```

Resolve the children first (`--close`, `--cancel`, `--defer`), then close the phase.

### Dry-run

Like every other write verb, `--dry-run` prints the envelope and exits without touching the database:

```sh
ipman --dry-run --close-phase auth-rewrite --summary "..." --comment "..."
```

The output includes `request_id: "dry-run-close-phase"` (or `"dry-run-cancel-phase"`) so it's easy to spot in pipelines.

## Logging: `IPMAN_LOG`

Set `IPMAN_LOG=info` to surface request-level logs on stderr; default is `warn`. Errors and warnings are always shown. This is purely a stderr behavior — no JSON output changes.

```sh
IPMAN_LOG=info ipman -N        # request log on stderr
ipman -N                       # silent on stderr unless something fails
```

## Tip on parse-level errors

When stdin can't be parsed as a request envelope (missing `protocol_version`, missing `request_id`, malformed JSON), ipman prints the standard `invalid_request` JSON response on stdout and adds one line on stderr:

```
{"request_id":"unknown","ok":false,"error":{"code":"invalid_request","message":"..."}}
tip: pipe `ipman --usage` for the CLI surface, or `ipman --next` for plan/cursor context.
```

The tip fires only at the parse boundary — once the envelope parses, op-level errors stay quiet.

## Documentation reorder

`README.md` now opens with `## Five-minute tour`, a pure-CLI walkthrough of `ipman --init`, `-N`, `--activate`, `--start`, `--close`. The JSON `plan.create` example moved into a new `## Programmatic surface` section. The intent is that a first-time reader sees a working CLI loop before they see a JSON envelope.

`.ipman/START-HERE.md` (regenerated on every `ipman --init` and `workspace.refresh_agent_docs`) follows the same pattern: `## Common Verbs (CLI)` precedes `## JSON Protocol` precedes `## Common Intents (JSON ops)`. Agents that read top-to-bottom now see the cheap surface first.

## Migration patterns

### From hand-rolled `phase.close` JSON

If you have shell scripts that pipe `phase.close` envelopes:

```sh
echo '{"protocol_version":2,"request_id":"r","actor":"agent",
       "op":"phase.close",
       "params":{"id":3,"outcome_summary":"...","closing_comment":"..."}}' | ipman
```

Replace with:

```sh
ipman --close-phase 3 --summary "..." --comment "..."
```

The wire envelope produced is identical (verifiable with `--dry-run`). `request_id` becomes `"dry-run-close-phase"` in dry-run mode and `"cli"` on real calls.

### From v2.1 CLI scripts

No change needed. v2.1 verbs (`--start`, `--close`, `--cancel`, `--defer`, `--current`, `--activate`, `--next`, `--dry-run`) behave identically. The new phase verbs are additive.

### From always-on info logs

If your scripts grep stderr for ipman info logs, set `IPMAN_LOG=info` to restore v2.1 behavior. Default behavior changed from "always log info" to "warn-and-above only".

---

## No-goals (preserved from v2.1)

- **No breaking wire changes.** `protocol_version` stays at `2`. The schema for `phase.close` is unchanged.
- **No parallel mutation path.** Every CLI verb dispatches the same JSON op an agent would send. There is no CLI-only side effect.
- **No CLI verb without a wire op.** A verb is a thin client over the protocol, never a substitute for it.
