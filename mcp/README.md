# ipman MCP server

A small Python adapter that exposes every `ipman` operation as an MCP tool over JSON-RPC 2.0 with LSP-style framing. Lets MCP-aware clients (Claude Desktop, Cursor, Continue, custom agent stacks) call ipman without piping JSON to stdin themselves.

## Requirements

- Python 3.10+ (uses `dict | None` syntax)
- `ipman` binary on `$PATH` (or set `IPMAN_BIN` to its path)
- An initialized workspace (`ipman init` has been run for this `IPMAN_HOME`)

No third-party Python dependencies.

## Run it

```sh
IPMAN_HOME=/path/to/project/.ipman \
IPMAN_BIN=$(which ipman) \
python3 mcp/ipman_mcp.py
```

The server reads JSON-RPC requests from stdin and writes responses to stdout, both using `Content-Length`-framed messages. It exits when stdin closes.

## How it works

On startup the server reads `$IPMAN_HOME/manifest.json` (auto-generated by `ipman init` and refreshable via `workspace.refresh_agent_docs`) and builds an MCP `tools/list` response with one tool per registered operation. Each tool's `inputSchema` is derived from the corresponding `.ipman/schemas/ipman.op.<entity>.<verb>.request.schema.json` file.

When the client invokes `tools/call`, the server:

1. Builds a request envelope: `{"protocol_version": 1, "request_id": "<id>", "actor": "mcp", "op": "<name>", "params": <arguments>}`.
2. Spawns the `ipman` binary, pipes the envelope to stdin.
3. Parses the JSON response and translates `ok: false` into MCP `isError: true`.

The Python process is stateless. Each tool call spawns a fresh `ipman` process. This is fine for typical agent workloads (sub-millisecond DB open with SQLCipher's prepared key) and avoids long-lived state in the bridge.

## Configuring an MCP client

### Claude Desktop / Claude Code

Add to your MCP config (`claude_desktop_config.json` or equivalent):

```json
{
  "mcpServers": {
    "ipman": {
      "command": "python3",
      "args": ["/absolute/path/to/ipman/mcp/ipman_mcp.py"],
      "env": {
        "IPMAN_HOME": "/absolute/path/to/your/project/.ipman",
        "IPMAN_BIN": "/absolute/path/to/ipman"
      }
    }
  }
}
```

### Cursor / Continue / generic MCP client

Same shape: command is `python3`, the script is the args, and the two env vars set the workspace and binary.

## Troubleshooting

- **"IPMAN_HOME is not set"** — the env var is missing or empty. Set it to the absolute path of your initialized workspace.
- **"ipman binary not found"** — the binary on `IPMAN_BIN` (or `ipman` on `$PATH`) is not callable. Run `make install` from the repo root or set `IPMAN_BIN` to the absolute path of the built binary.
- **Empty `tools/list`** — the workspace's `manifest.json` is missing. Run `ipman init` (or `workspace.refresh_agent_docs`) for that `IPMAN_HOME` and try again.
- **Tool returns `isError: true`** — read the embedded `text` content; it's the verbatim `error.code` and `error.message` from ipman's JSON envelope.
